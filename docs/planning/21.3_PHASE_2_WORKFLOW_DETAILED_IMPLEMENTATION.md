# Kế hoạch Triển khai Chi tiết Phase 2 (v1.1.0 - v1.6.0)

Tài liệu đặc tả chi tiết workflow, service, data models và queue jobs cho Giai đoạn 2 theo yêu cầu nâng cấp sản phẩm.

---

## 1. v1.1.0 — Achievement / Badge Engine

Hệ thống ghi nhận thành tựu (không thưởng lá/vật chất).

**Database Models:**
- `Achievement` (`code`, `name`, `description`, `is_repeatable`, `cooldown_period`)
- `UserAchievement` (`user_id`, `achievement_id`, `awarded_at`)

**Domain Service:** `app/Domain/Achievement/Services/AchievementService.php`
- `checkAndAward(int $userId): void` -> Được gọi sau khi settlement hoặc khi bet placed tùy badge.

**Workflow:**
1. Event `BetPlaced` hoặc `SettlementCompleted` trigger `CheckAchievementJob`.
2. `CheckAchievementJob` gọi `AchievementService::checkAndAward()`.
3. Kiểm tra điều kiện (ví dụ: `FIRST_WIN` kiểm tra nếu count bets status = WON là 1).
4. Insert vào `user_achievements` nếu thỏa mãn và chưa nhận.
5. Trigger `AchievementUnlocked` event.

---

## 2. v1.2.0 — Mission Engine

Hệ thống nhiệm vụ tuần/vòng (Mission).

**Database Models:**
- `Mission` (`code`, `title`, `description`, `type(weekly/round)`, `target_value`, `start_at`, `end_at`)
- `UserMission` (`user_id`, `mission_id`, `current_value`, `is_completed`, `completed_at`)

**Domain Service:** `app/Domain/Mission/Services/MissionService.php`
- `trackProgress(int $userId, string $action, int $value): void`
- `completeMission(int $userId, int $missionId): void`

**Workflow:**
1. Action xảy ra (đặt vé, thắng vé) bắn event.
2. Queue worker catch event gọi `MissionService::trackProgress()`.
3. Increment `current_value`. Nếu `>= target_value`, mark `is_completed` = true.

---

## 3. v1.3.0 — Notification System

Thông báo real-time & database.

**Package:** Dùng default Laravel Notifications (`database` driver).

**Domain Service:** `app/Domain/Notification/Services/NotificationService.php`
- `notifyMarketClosing(Market $market): void`
- `notifySettlementCompleted(Settlement $settlement): void`
- `notifyAchievementUnlocked(UserAchievement $ua): void`

**Workflow:**
1. Tạo Notifications classes: `MarketClosingNotification`, `SettlementDoneNotification`.
2. Schedule Job chạy mỗi phút tìm các Market có `close_at` trong 15p tới -> Gọi `notifyMarketClosing`.
3. Filament Native Database Notifications tích hợp ở Header để user thấy realtime.

---

## 4. v1.4.0 — Approval Workflow

Quy trình duyệt kết quả nhạy cảm trước khi xử lý.

**Database Models:** Thêm `approved_by` và `approved_at` vào các model `Settlement`, `Correction`.

**Domain Service:** `app/Domain/Approval/Services/ApprovalService.php`
- `requestApproval($model): void`
- `approve($model, int $adminId): void`
- `reject($model, int $adminId, string $reason): void`

**Workflow:**
1. Operator nhập kết quả, status chuyển thành `PENDING_APPROVAL`.
2. Settlement Manager thấy notification/badge ở Filament resource.
3. Manager xem preview, click "Approve".
4. Gọi `ApprovalService::approve()`, trigger job thực thi thực tế.

## 5. v1.5.0 — Correction Workflow

Sửa kết quả mà không xóa dữ liệu cũ (Audit-friendly).

**Database Models:**
- `SettlementCorrection` (`settlement_id`, `old_payout`, `new_payout`, `reason`, `status`)

**Domain Service:** `app/Domain/Settlement/Services/CorrectionService.php`
- `createCorrection(int $settlementId, array $newResults, string $reason): SettlementCorrection`
- `executeCorrection(SettlementCorrection $correction): void`

**Workflow:**
1. Admin phát hiện kết quả sai ở Market đã Settled.
2. Action "Correct Settlement": Nhập kết quả mới và lý do.
3. `createCorrection()` sinh bảng nháp. (Có thể gắn vào Approval Workflow).
4. Khi execute, tính `adjustment = new_payout - old_payout` cho từng bet.
5. Tạo `WalletLedger` loại `SETTLEMENT_CORRECTION` cộng/trừ số dư adjustment.
6. Đánh dấu bet status = `CORRECTED`.

## 6. v1.6.0 — Dashboard Analytics

Thống kê admin và Leaderboard nâng cao.

**Packages:** `leandrocfe/filament-apex-charts`, Excel Export/Import.

**Database Models:** Thêm `UserStatistic` table (đã định nghĩa ở script trước).

**Components:**
1. **Admin Widgets:**
   - `OverviewStatsWidget`: Tổng số lá lưu hành, lá khóa, tổng User active.
   - `BettingVolumeChart`: Chart đường biểu diễn số vé/ngày.
   - `MarketStatusListWidget`: Các market chuẩn bị đóng hoặc chưa nhập kết quả.
2. **Filament Pages (Player):**
   - Nâng cấp `LeaderboardPage` có tab chọn: Mùa giải | Tuần | Vòng Đấu | ROI | Cao thủ Tỉ số.
3. **Exports:**
   - Sử dụng Filament Export Actions để tải Excel cho danh sách Bets, Ledger và Bảng xếp hạng.
